Workflow shapes that come up again and again, written with the Python SDK. Each one relies on the same guarantee: a step the journal has recorded is not repeated when the workflow resumes.

---

## Compensation (saga)

When a workflow changes several systems and a later step fails, undo the earlier steps. `Saga` collects a compensation after each step that succeeds and runs them newest first:

<$CodeSample path="python/patterns/saga.py" region="saga" />

- Compensations are tasks, so they are journaled and retried like any task. A compensation that still fails is logged and the rest still run.
- Register a compensation after its step succeeds, so it can use the step's result (the reservation id here). `saga.add_step(action, compensation)` runs an action and registers its compensation in one call when the compensation doesn't need the result.
- `except Exception` is safe here: the signal the SDK uses to suspend a workflow is not an `Exception`, so a workflow that is merely waiting for a task never compensates.

## Idempotent side effects

Tasks run at least once: a retried or reassigned attempt may repeat side effects that a previous attempt already made. Pass the services you call an idempotency key that stays the same across attempts; see [Tasks run at least once](/guides/sdk/python/tasks#tasks-run-at-least-once).

Starting a workflow is idempotent through its id: give each piece of work a workflow id derived from it (an order id, a webhook delivery id), and a repeated start is refused rather than run twice. See [duplicate starts](/guides/sdk/python/client#duplicate-starts).
