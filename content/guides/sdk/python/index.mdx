Write workflows and tasks as plain `async` Python functions. The engine journals each step, and a run that is interrupted resumes on any worker from the last step it completed.

---

## Installation

```bash
# pip
pip install orcher-sdk

# poetry
poetry add orcher-sdk

# uv
uv add orcher-sdk
```

The package is `orcher-sdk` and it imports as `orcher`. The package named `orcher` on PyPI is the command-line tool, not the SDK.

### Requirements

- Python 3.11 or later (CPython).
- An Orcher engine to connect to. The [quickstart](/guides/getting-started/quickstart) starts one on your machine.
- pip installs a prebuilt wheel on macOS (arm64 and x86_64) and Linux (x86_64 and aarch64, glibc or musl). Anywhere else it builds the SDK's native core from source, which needs a Rust toolchain.

The SDK is pre-1.0 (this guide covers `orcher-sdk` 0.4): its API may change between minor releases, and each breaking change is listed in the [changelog](https://github.com/orcher-io/sdk-py/blob/main/CHANGELOG.md).

## Quick start

### 1. Define tasks

A task is an `async` function decorated with `@task`. Tasks are where side effects go: calls to other services, database writes, emails. The engine retries a failed task according to its retry policy.

<$CodeSample path="python/sdk_overview/tasks.py" region="tasks" />

### 2. Define a workflow

A workflow is an `async` function decorated with `@workflow`. It decides which tasks run and in what order. Its code is replayed from the journal every time it resumes, so it must be deterministic: do I/O in tasks, not in the workflow.

<$CodeSample path="python/sdk_overview/workflows.py" region="workflow" />

### 3. Run a worker

A worker connects to the engine, registers every workflow and task whose module has been imported, and runs them.
