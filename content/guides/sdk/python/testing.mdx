`orcher.testing.TestWorkflowEnvironment` runs a workflow in memory, with no engine and no worker. Every task the workflow calls is answered by a mock you set up by task name, the environment records the calls, and `ctx.sleep()` moves a test clock instead of waiting.

The examples use [pytest](https://docs.pytest.org/) with [pytest-asyncio](https://pytest-asyncio.readthedocs.io/).

## Failures

`.throws()` makes a mocked task raise. The exception reaches the workflow as raised, so a test can also cover a workflow that catches it:

<$CodeSample path="python/testing/test_orders.py" region="failure" />

In the environment a mocked task is called once: there are no retries, and a failure is not turned into the `TaskError` a real worker raises after the retries are used up. A workflow that catches `TaskError` needs the mock to throw one to take that path.

## Time

`ctx.sleep()` advances the environment's clock by its duration instead of waiting, so a workflow that sleeps for an hour finishes at once:

<$CodeSample path="python/testing/test_orders.py" region="time" />

`env.advance_time(ms)`, `env.advance_time_to(datetime)` and `env.set_current_time(datetime)` move the clock directly.

## What the environment supports

The workflow runs with a test context, not a `WorkflowContext`, and that context supports only part of the API:

| Supported | Not supported |
|---|---|
| `execute_task`, `sleep`, `set_state`, `get_state(key)` (no default argument), `now()`, `is_replaying`, `workflow_id`, `workflow_type` | `execute`, `ctx.time`, `ctx.random`, `ctx.info`, events, child workflows, sessions, `restart_fresh`, queries and updates |

A workflow that uses the unsupported parts fails in the environment with `AttributeError` or `TypeError`. Test those workflows against a real engine instead: the [quickstart](/guides/getting-started/quickstart) starts one locally.
