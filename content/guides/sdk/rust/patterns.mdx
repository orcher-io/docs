Patterns that come up often, written against the Rust SDK. Each one is complete code that compiles against `orcher-sdk` 0.7.

One rule runs through all of them: a step that hasn't finished yet returns the *suspension* error, and it must reach the worker unchanged. Handle the specific errors you mean to handle and return the rest ([Handling Failures](/guides/sdk/rust/workflows#handling-failures)).

---

## Saga (Compensation)

When a business operation spans several services, undo the steps that succeeded if a later one fails. The SDK's `Saga` keeps the list of compensations and runs them in reverse order:

<$CodeSample path="rust/sdk-patterns/src/lib.rs" region="saga" />

- `add_step(&ctx, task, input).with_compensation(task).execute()` runs the task and, once it succeeds, registers the compensation with the same input. If the task fails, the compensations registered so far run, last first, and the task's error is returned.
- `execute_without_compensation()` runs a step with nothing to undo; its failure doesn't trigger compensation.
- `saga.add_compensation(task, input)` registers a compensation for a step you ran yourself, and `saga.compensate(&ctx)` runs them on demand.
- A failing compensation doesn't stop the others. Give compensations generous retries and make them safe to repeat.
- `Saga` passes the suspension through, so it never compensates a step that is merely still running. It is in `orcher_sdk::workflow`.

## Long-Running Loops

A workflow that loops for weeks, polling or processing a stream, grows its history with every step, and replay reads all of it. Restart it with a fresh history every so many iterations, passing on the state it needs, with `ctx.restart_fresh_with` ([Workflows](/guides/sdk/rust/workflows#restarting-with-a-fresh-history)).

## One Task per Item, or Batches

One task per item retries each item on its own and shows each one's outcome, at the cost of a journal entry and a scheduling round trip per item. A task per batch has less overhead, but retries the whole batch when one item fails and must keep its input and result within the payload limit. Choose by how independent the items are, and measure with your own workload.
