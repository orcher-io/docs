Patterns for common workflow shapes, written with the TypeScript SDK. The tasks they call are
defined with `@Tasks()` classes and `createTaskRefs()`, as in [Tasks](/guides/sdk/typescript/tasks).

---

## Saga (Compensation)

When a workflow books several things across services, a failure halfway must undo what was
already done. The SDK's `Saga` keeps the list of compensations and runs them newest first:

<$CodeSample path="typescript/src/patterns/saga.ts" region="saga" />

The `isWorkflowSuspension(err)` check is not optional. Waiting for a task makes
`ctx.executeTask()` throw a suspension, and a `catch` without the check would compensate
on every wait: a healthy run would cancel its own bookings. Register each compensation only once
its step has succeeded, so a failed step is never "undone".

`saga.addStep(action, compensation)` runs a step and registers its compensation in one call. It
compensates and re-throws when the step fails, and lets a suspension through:

<$CodeSample path="typescript/src/patterns/saga.ts" region="add-step" />

`compensate()` runs each compensation once. A compensation that fails is logged and skipped, and
the rest still run. Compensations are ordinary tasks, so they are journaled and retried like any
other; make them idempotent.

## Starting Work Once

Use the business identity of the work as the workflow id, so a repeated request (a retried
webhook, a double click) finds the run that is already going instead of starting a second one.
See [starting a workflow once](/guides/sdk/typescript/client#starting-a-workflow-once) for the
reuse policies and the sample.

Keep every task input and result under the payload limit, 8 MiB on a default engine. For more

time, start a fresh journal now and then with
