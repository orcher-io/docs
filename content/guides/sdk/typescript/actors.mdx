An actor is an addressable piece of state with operations on it. Each actor has a type and a
key; its state lives in the engine as named values, so any worker can run its operations.
Operations on one key are processed one at a time, unless they are declared read-only.

---

## Defining an Actor

<$CodeSample path="typescript/src/actors/cart.ts" region="actor" />

- `@Actor({ name })` names the actor type; without `name`, the class name is used.
- Each `@Operation()` method takes an `ActorContext` first and at most one input.
- `ctx.state` reads and writes the actor's state in the engine: `get<T>(key)`, `set(key, value)`,
  `delete(key)` and `listKeys(prefix?)`. Values are stored as JSON.
- The actor class is built anew for each operation, by the worker's container, so constructor
  parameters are injected as for [task classes](/guides/sdk/typescript/tasks#dependency-injection).
  Keep state in `ctx.state`, not in fields.

A worker polls for actor operations only when actors are registered in its process; register
them by importing the module, as with workflows and tasks.

---

## Operation Modes

| Mode | Behavior |
|------|----------|
| `'exclusive'` (default) | Runs alone: no other operation on the same key runs at the same time |
| `'shared'` | May run alongside other shared operations on the same key; an exclusive operation waits for them |

Declare an operation `shared` only if it does not change state.

## ActorContext Reference

| Member | Description |
|--------|-------------|
| `ctx.state` | The actor's state in the engine: `get`, `set`, `delete`, `listKeys` |
| `ctx.actorName` / `ctx.key` | The actor type and key |
| `ctx.operationName` / `ctx.operationId` | The operation being run |
| `ctx.mode` | `'exclusive'` or `'shared'` |
| `ctx.metadata` | Metadata sent with the operation |
