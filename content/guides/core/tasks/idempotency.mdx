Tasks should be designed to be safely retried without causing duplicate side effects.

### Using Idempotency Keys

Pass a unique idempotency key with external API calls so that retries don't create duplicate side effects. The `TaskContext` provides a task token and attempt number that you can combine to build a stable key for each execution attempt.

<Tabs
  scrollable
  size="small"
  type="underlined"
  defaultActiveId="rust"
  queryGroup="language"
>

<TabPanel id="rust" label="Rust">

```rust
#[task(
name = "charge_card",
retry = 3  // ← Task may be retried up to 3 times
)]
pub async fn charge_card(
_ctx: TaskContext,
input: PaymentInput,
) -> Result<ChargeResult> {
// Get Stripe API client
let stripe_client = get_stripe_client();

// Create charge with idempotency key
let charge = stripe::Charge::create(
    &stripe_client,
    ChargeParams {
        amount: input.amount,        // e.g., 5000 (= $50.00)
        currency: "usd",              // USD currency
        source: input.card_token,     // Customer's card token

        // ⭐ THE KEY LINE: Idempotency key prevents duplicate charges
        // Format: "order_12345"
        // If Stripe sees this key again, it returns the original charge
        // without creating a new one
        idempotency_key: Some(format!("order_{}", input.order_id)),
        ..Default::default()
    }
).await?;

// Return charge details
Ok(ChargeResult {
    charge_id: charge.id,         // e.g., "ch_abc123"
    amount: charge.amount,         // 5000
    status: "succeeded".to_string(),
})
}
```

**What happens on retry:**
```rust
// First execution (workflow run #1):
// 1. Orcher executes task
// 2. Stripe receives request with idempotency_key="order_12345"
// 3. Stripe creates charge, stores key
// 4. Returns charge_id="ch_abc123"
// 5. Orcher saves result to journal

// Second execution (if workflow retried):
// 1. Orcher checks journal first
// 2. Finds cached result: charge_id="ch_abc123"
// 3. Returns cached result immediately (NO API call to Stripe)
// 4. Customer charged only once ✓

// Third execution (if task manually re-run outside workflow):
// 1. Task executes again
// 2. Stripe receives request with same idempotency_key="order_12345"
// 3. Stripe recognizes the key
// 4. Returns original charge_id="ch_abc123" (NO new charge created)
// 5. Customer still charged only once ✓
```

**Key Takeaways:**
- Idempotency key should be based on workflow/order ID, not timestamps
- Use same key format consistently: `order_{orderId}`, `payment_{paymentId}`
- External system (Stripe) deduplicates based on key
- Orcher's journal provides first layer of deduplication
- Idempotency key provides second layer (if task runs outside workflow)

### Strategy 2: Database Upsert Pattern

**Concept:** Use database operations that are naturally idempotent (INSERT ON CONFLICT, UPSERT, atomic UPDATE).

**When to Use:**
- Database writes
- Inventory management
- Counter updates
- Status changes

**How It Works:**

Instead of read-modify-write (which is NOT idempotent), use atomic database operations that produce the same result when run multiple times.

**Complete Example with Breakdown:**

<Tabs
  scrollable
  size="small"
  type="underlined"
  defaultActiveId="rust"
  queryGroup="language"
>

<TabPanel id="rust" label="Rust">

```rust
#[task(name = "update_inventory")]
pub async fn update_inventory(
_ctx: TaskContext,
input: InventoryUpdate,
) -> Result<()> {
let db = get_database();

// Use UPSERT (INSERT ... ON CONFLICT) for idempotency
db.execute(
    "INSERT INTO inventory (product_id, quantity, updated_at)
     VALUES ($1, $2, NOW())
     ON CONFLICT (product_id)
     DO UPDATE SET
       quantity = $2,
       updated_at = NOW()",
    &[&input.product_id, &input.quantity]
).await?;

Ok(())
}
```

### Check-Before-Execute Pattern

Before performing a non-idempotent operation, check whether it has already been done. This pattern is useful when the external system doesn't support idempotency keys — you query the current state first and skip the operation if it was already applied.

<Tabs
  scrollable
  size="small"
  type="underlined"
  defaultActiveId="rust"
  queryGroup="language"
>

<TabPanel id="rust" label="Rust">

```rust
#[task(name = "send_welcome_email")]
pub async fn send_welcome_email(
_ctx: TaskContext,
user_id: String,
) -> Result<EmailResult> {
let db = get_database();

// Check if email was already sent
let already_sent: bool = db.query_one(
    "SELECT EXISTS(
       SELECT 1 FROM sent_emails
       WHERE user_id = $1 AND email_type = 'welcome'
     )",
    &[&user_id]
).await?;

if already_sent {
    tracing::info!("Email already sent to user {}", user_id);
    return Ok(EmailResult {
        message_id: "already_sent".to_string(),
        sent: false,
    });
}

// Send email
let result = email_service::send_welcome(&user_id).await?;

// Record that email was sent
db.execute(
    "INSERT INTO sent_emails (user_id, email_type, message_id)
     VALUES ($1, 'welcome', $2)",
    &[&user_id, &result.message_id]
).await?;

Ok(result)
}
```

# Record that email was sent

    user_id,

)

### Error Handling

Tasks should handle errors appropriately and return meaningful error messages.

<Tabs
  scrollable
  size="small"
  type="underlined"
  defaultActiveId="rust"
  queryGroup="language"
>

<TabPanel id="rust" label="Rust">

```rust
use anyhow::{Context, Result};

#[task(
name = "fetch_external_data",
retry = 5
)]
pub async fn fetch_external_data(
ctx: TaskContext,
url: String,
) -> Result<ApiResponse> {
let response = reqwest::get(&url)
    .await
    .context("Failed to connect to API")?;

match response.status() {
    status if status.is_success() => {
        let data = response.json().await?;
        Ok(data)
    }
    status if status.is_server_error() => {
        // 5xx errors are transient - should retry
        Err(anyhow::anyhow!(
            "Server error (will retry): HTTP {}",
            status
        ))
    }
    status => {
        // 4xx errors are permanent - don't retry
        Err(anyhow::anyhow!(
            "Client error (permanent): HTTP {}",
            status
        ))
    }
}
}
```

</TabPanel>

<TabPanel id="typescript" label="TypeScript">

```typescript
// Inside a @Tasks() class:
@Task({
  name: 'fetchExternalData',
  retryPolicy: {
    maxAttempts: 5,
    nonRetryableErrorTypes: ['ClientError'],
  },
})
async fetchExternalData(
  _ctx: TaskContext,
  url: string
): Promise<ApiResponse> {
  const response = await fetch(url);

  if (response.ok) {
return response.json();
  }

  if (response.status >= 500) {
// 5xx errors are transient - should retry
throw new Error(`Server error (will retry): HTTP ${response.status}`);
  }

  // 4xx errors are permanent - mark as non-retryable
  const error = new Error(`Client error: HTTP ${response.status}`);
  error.name = 'ClientError';
  throw error;
}
```

</TabPanel>

<TabPanel id="python" label="Python">

```python
import httpx
from orcher import task, TaskContext
from orcher.errors import ApplicationFailure

@task(
name="fetch_external_data",
retry_policy={"max_attempts": 5},
)
async def fetch_external_data(ctx: TaskContext, url: str) -> dict:
async with httpx.AsyncClient() as client:
    response = await client.get(url)

if response.is_success:
    return response.json()

if response.status_code >= 500:
    # 5xx errors are transient - should retry
    raise RuntimeError(
        f"Server error (will retry): HTTP {response.status_code}"
    )

# 4xx errors are permanent - mark as non-retryable
raise ApplicationFailure(
    message=f"Client error: HTTP {response.status_code}",
    error_type="ClientError",
    retryable=False,
)
```
