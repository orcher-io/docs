Workflow code **must be deterministic** — meaning it must produce the same sequence of context calls every time it executes with the same inputs. This is a fundamental requirement, not a suggestion.

The reason is replay. When a workflow resumes after a crash, the runtime re-executes your workflow function from the beginning. It matches each context call to a journal entry by sequence number: the first `execute_task` in your code corresponds to journal entry #1, the second to #2, and so on. If replay encounters a different sequence of calls than the original execution, the journal entries won't match and the workflow will fail with a **non-determinism error**.

### What is Safe

Any operation that produces the same result every time is safe to use directly in workflow code:

- **Pure computation** — math, string manipulation, data transformation
- **Context methods** — `execute_task`, `execute`, `sleep`, `wait_for_event`, `execute_child_workflow` (these are journaled)
- **Branching on task results** — `if`/`else` based on journaled values is safe because the same journaled values will be replayed

```rust
use orcher::prelude::*;
use anyhow::Result;
use std::time::Duration;

#[workflow(name = "safe_workflow", version = "1.0.0")]
pub async fn safe_workflow(
    ctx: WorkflowContext,
    input: MyInput,
) -> Result<String> {
    // Safe: Pure computation (same input always gives same output)
    let computed = input.amount * 2;

    // Safe: Using task execution (result is journaled)
    let result: String = ctx
        .execute_task(get_data, ())
        .await?;

    // Safe: Using workflow context (sleep is journaled)
    ctx.sleep(Duration::from_secs(60)).await?;

    Ok(result)
}
```

### What is NOT Safe

Operations that can return different values on each execution will break replay. These must always be wrapped in tasks:

- **Current time** — `DateTime::now()`, `new Date()`, `datetime.now()` return different values on replay. If you need the current time, get it inside a task and return it as a result.
- **Random values** — `rand::random()`, `Math.random()`, `random.randint()` produce different values on each call. Wrap randomness in a task.
- **UUIDs** — UUID generation is random. Generate UUIDs inside tasks.
- **Direct I/O** — Network calls, file reads, database queries outside of tasks are not journaled. If the result differs on replay, your workflow will diverge.

```rust
use orcher::prelude::*;
use anyhow::Result;
use std::time::SystemTime;
use rand::Rng;

#[workflow(name = "unsafe_workflow", version = "1.0.0")]
pub async fn unsafe_workflow(
    ctx: WorkflowContext,
    _input: MyInput,
) -> Result<String> {
    // UNSAFE: Current time changes on replay
    let now = SystemTime::now();

    // UNSAFE: Random values differ on replay
    let random = rand::thread_rng().gen::<u32>();

    // UNSAFE: Direct network call (not journaled)
    let response = reqwest::get("https://api.example.com").await?;

    // CORRECT: Use execute() or execute_task() for all external interactions
    let result: String = ctx
        .execute("fetch_data", || async {
            let resp = reqwest::get("https://api.example.com").await?;
            Ok(resp.text().await?)
        })
        .await?;

    Ok(result)
}
```
