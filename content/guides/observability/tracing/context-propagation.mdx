Trace context is propagated across service boundaries using W3C `traceparent` headers. The `tracing-export` feature enables this.

## Injecting Context

Add trace context to outgoing HTTP requests:

```rust
use orcher_monitoring::tracing::inject_context;
use reqwest::Client;

async fn call_external_service(data: &ServiceRequest) -> Result<ServiceResponse> {
    let client = Client::new();
    let mut headers = reqwest::header::HeaderMap::new();

    // Inject W3C traceparent header
    inject_context(&mut headers);

    let response = client
        .post("https://api.example.com/process")
        .headers(headers)
        .json(data)
        .send()
        .await?;

    Ok(response.json().await?)
}
```

## Extracting Context

Continue a trace from incoming HTTP requests:

```rust
use orcher_monitoring::tracing::extract_context;

async fn handle_request(req: Request) -> Response {
    // Extract trace context from incoming headers
    let parent_context = extract_context(req.headers());

    let span = if let Some(ctx) = parent_context {
        tracing::info_span!("handle_request", otel.parent = ctx)
    } else {
        tracing::info_span!("handle_request")
    };

    let _guard = span.enter();
    // All child spans inherit this trace context
    process_request(req).await
}
```

## Trace and Span IDs

Access the current trace/span IDs for correlation with logs and external systems:

```rust
use orcher_monitoring::tracing::{current_trace_id, current_span_id};

let trace_id = current_trace_id();  // Option<String>
let span_id = current_span_id();    // Option<String>

tracing::info!(
    trace_id = ?trace_id,
    span_id = ?span_id,
    "Processing with trace correlation"
);
```
