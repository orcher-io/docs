Child workflows let you break complex orchestrations into smaller, independently testable components. Each child runs with its own execution context and lifecycle — if a child fails, the parent can catch the error, try a fallback, or compensate. This pattern maps naturally to microservice boundaries: one child workflow per service domain (payments, inventory, shipping), composed by a parent that coordinates the overall transaction.

## How it works

The parent reads like a function calling functions — and that's the point. Each `start_child_workflow(...)` here is awaited before the next begins, because the phases depend on each other: no payment without a reservation, no shipment without payment. Note the example also mixes granularity deliberately: two phases are child workflows, the third is a plain task.

```rust
use orcher::prelude::*;
use anyhow::Result;

// Child workflow: Validate and reserve inventory
#[task]
async fn check_stock(items: Vec<OrderItem>) -> Result<StockResult> {
    // Call inventory service API
    inventory_client::check_availability(items).await
}

#[task]
async fn reserve_items(reservation: ReservationRequest) -> Result<ReservationId> {
    inventory_client::reserve(reservation).await
}

#[workflow(name = "reserve_inventory", version = "1.0.0")]
async fn reserve_inventory(
    ctx: WorkflowContext,
    items: Vec<OrderItem>,
) -> Result<InventoryReservation> {
    let stock = ctx.execute_task(check_stock, items.clone()).await?;
    if !stock.all_available {
        return Err(anyhow::anyhow!("Items out of stock: {:?}", stock.missing));
    }
    let reservation_id = ctx.execute_task(reserve_items, ReservationRequest {
        items,
        ttl_minutes: 15,
    }).await?;
    Ok(InventoryReservation { reservation_id, items: stock.confirmed })
}

// Child workflow: Process payment
#[task]
async fn charge_card(input: ChargeInput) -> Result<ChargeResult> {
    payment_client::charge(input).await
}

#[task]
async fn send_receipt(charge_id: String) -> Result<()> {
    email_client::send_receipt(charge_id).await
}

#[workflow(name = "process_payment", version = "1.0.0")]
async fn process_payment(
    ctx: WorkflowContext,
    input: PaymentInput,
) -> Result<PaymentResult> {
    let charge = ctx.execute_task(charge_card, ChargeInput {
        amount: input.amount,
        currency: input.currency,
        method: input.method,
    }).await?;
    ctx.execute_task(send_receipt, charge.id.clone()).await?;
    Ok(PaymentResult { charge_id: charge.id, status: "completed".into() })
}

// Parent workflow: Compose child workflows
#[task]
async fn create_shipment(input: ShipmentInput) -> Result<TrackingNumber> {
    shipping_client::create(input).await
}

#[workflow(name = "order_fulfillment", version = "1.0.0")]
async fn order_fulfillment(
    ctx: WorkflowContext,
    order: OrderInput,
) -> Result<OrderResult> {
    // Phase 1: Reserve inventory (child workflow)
    let reservation = ctx.start_child_workflow(
        reserve_inventory, order.items.clone(),
    ).await?;

    // Phase 2: Process payment (child workflow)
    let payment = ctx.start_child_workflow(
        process_payment, order.payment.clone(),
    ).await?;

    // Phase 3: Ship order (task)
    let tracking = ctx.execute_task(create_shipment, ShipmentInput {
        reservation_id: reservation.reservation_id,
        address: order.shipping_address,
    }).await?;

    Ok(OrderResult {
        payment_id: payment.charge_id,
        tracking_number: tracking,
    })
}
```

```typescript
import {
  Workflow,
  Tasks,
  Task,
  WorkflowContext,
  createTaskRefs,
  WorkerBuilder,
} from '@orcher/sdk';

// Child workflow tasks: Inventory
@Tasks()
class InventoryTasks {
  @Task()
  async checkStock(items: OrderItem[]): Promise<StockResult> {
    return await inventoryClient.checkAvailability(items);
  }

  @Task()
  async reserveItems(req: ReservationRequest): Promise<string> {
    return await inventoryClient.reserve(req);
  }
}

const inventoryTasks = createTaskRefs(InventoryTasks);

// Child workflow: Reserve inventory
@Workflow({ name: 'reserve_inventory', version: '1.0.0' })
class ReserveInventory {
  async run(ctx: WorkflowContext, items: OrderItem[]): Promise<InventoryReservation> {
    const stock = await ctx.executeTask(inventoryTasks.checkStock, items);
    if (!stock.allAvailable) {
      throw new Error(`Items out of stock: ${stock.missing.join(', ')}`);
    }
    const reservationId = await ctx.executeTask(inventoryTasks.reserveItems, {
      items,
      ttlMinutes: 15,
    });
    return { reservationId, items: stock.confirmed };
  }
}

// Child workflow tasks: Payments
@Tasks()
class PaymentTasks {
  @Task()
  async chargeCard(input: ChargeInput): Promise<ChargeResult> {
    return await paymentClient.charge(input);
  }

  @Task()
  async sendReceipt(chargeId: string): Promise<void> {
    await emailClient.sendReceipt(chargeId);
  }
}

const paymentTasks = createTaskRefs(PaymentTasks);

// Child workflow: Process payment
@Workflow({ name: 'process_payment', version: '1.0.0' })
class ProcessPayment {
  async run(ctx: WorkflowContext, input: PaymentInput): Promise<PaymentResult> {
    const charge = await ctx.executeTask(paymentTasks.chargeCard, {
      amount: input.amount,
      currency: input.currency,
      method: input.method,
    });
    await ctx.executeTask(paymentTasks.sendReceipt, charge.id);
    return { chargeId: charge.id, status: 'completed' };
  }
}

// Parent workflow tasks
@Tasks()
class ShippingTasks {
  @Task()
  async createShipment(input: ShipmentInput): Promise<string> {
    return await shippingClient.create(input);
  }
}

const shippingTasks = createTaskRefs(ShippingTasks);

// Parent workflow: Compose child workflows
@Workflow({ name: 'order_fulfillment', version: '1.0.0' })
class OrderFulfillment {
  async run(ctx: WorkflowContext, order: OrderInput): Promise<OrderResult> {
    // Phase 1: Reserve inventory (child workflow)
    const reservation = await ctx.startChildWorkflow(
      ReserveInventory, order.items,
    );

    // Phase 2: Process payment (child workflow)
    const payment = await ctx.startChildWorkflow(
      ProcessPayment, order.payment,
    );

    // Phase 3: Ship order (task)
    const tracking = await ctx.executeTask(shippingTasks.createShipment, {
      reservationId: reservation.reservationId,
      address: order.shippingAddress,
    });

    return { paymentId: payment.chargeId, trackingNumber: tracking };
  }
}
```

Each child workflow has its own execution history and can be tested independently. The parent catches child failures and can retry, fall back to alternatives, or compensate — exactly like calling functions in regular code, but with automatic journaling and crash recovery.

## Child workflow or plain task?

The example draws the line deliberately, and it's the decision you'll make most often with this pattern:

## Design notes

- **Sequential here, parallel when independent.** These phases depend on each other, so each child is awaited immediately. When the units are independent — sources, regions, partitions — collect the handles first and await them together, as in [multi-service deployment](/guides/use-cases/distributed-systems/multi-service-deployment).
- **A child failure is the parent's decision point.** Out-of-stock propagates from `reserve_inventory` as an ordinary error the parent can catch: retry, fall back to another warehouse, or [compensate what already completed](/guides/use-cases/distributed-systems/saga-pattern). The child stays simple; policy lives in the parent.
- **Children are real workflows.** `reserve_inventory` and `process_payment` can be started directly — in tests, from other parents, or by themselves in production. Composition is reuse, not just decomposition.
- **Keep the hierarchy shallow.** Parent → children mapped to service domains is usually enough; grandchildren of grandchildren make execution history hard to follow. See [Best Practices](/guides/use-cases/distributed-systems/best-practices).
