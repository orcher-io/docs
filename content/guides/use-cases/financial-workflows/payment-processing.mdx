The core payment pattern: charge the customer, reserve inventory, and send a confirmation. If any step fails, you compensate the previously completed steps — refunding the charge and releasing the inventory reservation — with logic you define; Orcher runs those compensations durably, retrying until they complete even across crashes. This is the saga pattern applied to payment processing.

## How it works

Look closely and this workflow applies a **different failure policy to every step** — that's the real design work in a payment saga. Failing early costs nothing; failing after money moved requires compensation; and some steps aren't worth failing over at all.

```rust
use orcher::prelude::*;
use anyhow::Result;
use serde::{Deserialize, Serialize};

#[derive(Debug, Clone, Serialize, Deserialize)]
struct PaymentInput {
    order_id: String,
    customer_id: String,
    amount: f64,
    currency: String,
    idempotency_key: String,
}

#[derive(Debug, Clone, Serialize, Deserialize)]
struct PaymentResult {
    charge_id: String,
    status: String,
    order_id: String,
}

#[derive(Debug, Clone, Serialize, Deserialize)]
struct ChargeResult {
    charge_id: String,
    status: String,
}

#[task]
async fn validate_payment(input: PaymentInput) -> Result<PaymentInput> {
    // Validate card, check limits, verify customer
    if input.amount <= 0.0 {
        anyhow::bail!("Invalid payment amount");
    }
    Ok(input)
}

#[task]
async fn charge_payment_gateway(
    amount: f64, currency: String, idempotency_key: String,
) -> Result<ChargeResult> {
    // Call Stripe/Braintree with idempotency key to prevent double charges
    let charge = gateway::create_charge(amount, &currency, &idempotency_key).await?;
    Ok(ChargeResult { charge_id: charge.id, status: "succeeded".to_string() })
}

#[task]
async fn reserve_inventory(order_id: String) -> Result<()> {
    // Reserve items in warehouse system
    warehouse::reserve(&order_id).await?;
    Ok(())
}

#[task]
async fn refund_charge(charge_id: String) -> Result<()> {
    // Compensating action: refund the charge
    gateway::refund(&charge_id).await?;
    Ok(())
}

#[task]
async fn send_confirmation(customer_id: String, order_id: String) -> Result<()> {
    // Send order confirmation email
    email::send_receipt(&customer_id, &order_id).await?;
    Ok(())
}

#[workflow(name = "process_payment", version = "1.0.0")]
pub async fn process_payment(
    ctx: WorkflowContext,
    input: PaymentInput,
) -> Result<PaymentResult> {
    // Step 1: Validate
    let validated = ctx.execute_task(validate_payment, input.clone()).await?;

    // Step 2: Charge payment gateway (with idempotency key)
    let charge = ctx.execute_task(charge_payment_gateway, (
        validated.amount, validated.currency.clone(), validated.idempotency_key.clone()
    )).await?;

    // Step 3: Reserve inventory — compensate on failure
    if let Err(e) = ctx.execute_task(reserve_inventory, validated.order_id.clone()).await {
        // Saga compensation: refund the charge
        ctx.execute_task(refund_charge, charge.charge_id.clone()).await?;
        return Err(e);
    }

    // Step 4: Send confirmation (best-effort, don't fail the payment)
    let _ = ctx.execute_task(send_confirmation, (
        validated.customer_id.clone(), validated.order_id.clone()
    )).await;

    Ok(PaymentResult {
        charge_id: charge.charge_id,
        status: "completed".to_string(),
        order_id: validated.order_id,
    })
}
```

```typescript
import { Workflow, Tasks, Task, WorkflowContext, createTaskRefs } from '@orcher/sdk';

interface PaymentInput {
  orderId: string;
  customerId: string;
  amount: number;
  currency: string;
  idempotencyKey: string;
}

interface PaymentResult {
  chargeId: string;
  status: string;
  orderId: string;
}

interface ChargeResult {
  chargeId: string;
  status: string;
}

@Tasks()
class PaymentTasks {
  @Task()
  async validatePayment(input: PaymentInput): Promise<PaymentInput> {
    if (input.amount <= 0) throw new Error('Invalid payment amount');
    return input;
  }

  @Task()
  async chargePaymentGateway(
    amount: number, currency: string, idempotencyKey: string
  ): Promise<ChargeResult> {
    const charge = await gateway.createCharge(amount, currency, idempotencyKey);
    return { chargeId: charge.id, status: 'succeeded' };
  }

  @Task()
  async reserveInventory(orderId: string): Promise<void> {
    await warehouse.reserve(orderId);
  }

  @Task()
  async refundCharge(chargeId: string): Promise<void> {
    await gateway.refund(chargeId);
  }

  @Task()
  async sendConfirmation(customerId: string, orderId: string): Promise<void> {
    await email.sendReceipt(customerId, orderId);
  }
}

const tasks = createTaskRefs(PaymentTasks);

@Workflow({ name: 'process_payment', version: '1.0.0' })
class ProcessPaymentWorkflow {
  async run(ctx: WorkflowContext, input: PaymentInput): Promise<PaymentResult> {
    // Step 1: Validate
    const validated = await ctx.executeTask(tasks.validatePayment, input);

    // Step 2: Charge payment gateway (with idempotency key)
    const charge = await ctx.executeTask(
      tasks.chargePaymentGateway, validated.amount, validated.currency, validated.idempotencyKey
    );

    // Step 3: Reserve inventory — compensate on failure
    try {
      await ctx.executeTask(tasks.reserveInventory, validated.orderId);
    } catch (e) {
      // Saga compensation: refund the charge
      await ctx.executeTask(tasks.refundCharge, charge.chargeId);
      throw e;
    }

    // Step 4: Send confirmation (best-effort, don't fail the payment)
    try {
      await ctx.executeTask(tasks.sendConfirmation, validated.customerId, validated.orderId);
    } catch { /* non-critical */ }

    return {
      chargeId: charge.chargeId,
      status: 'completed',
      orderId: validated.orderId,
    };
  }
}
```

from dataclasses import dataclass

@dataclass
class PaymentInput:
    order_id: str
    customer_id: str
    amount: float
    currency: str
    idempotency_key: str

@dataclass
class PaymentResult:
    charge_id: str
    status: str
    order_id: str

    charge_id: str
    status: str

@task
async def validate_payment(input: PaymentInput) -> PaymentInput:
    if input.amount <= 0:
        raise ValueError("Invalid payment amount")
    return input

@task
async def charge_payment_gateway(
    amount: float, currency: str, idempotency_key: str
) -> ChargeResult:
    charge = await gateway.create_charge(amount, currency, idempotency_key)
    return ChargeResult(charge_id=charge.id, status="succeeded")

@task
async def reserve_inventory(order_id: str) -> None:
    await warehouse.reserve(order_id)

@task
async def refund_charge(charge_id: str) -> None:
    await gateway.refund(charge_id)

@task
async def send_confirmation(customer_id: str, order_id: str) -> None:
    await email.send_receipt(customer_id, order_id)

@workflow(name="process_payment", version="1.0.0")
async def process_payment(ctx: WorkflowContext, input: PaymentInput) -> PaymentResult:
    # Step 1: Validate
    validated = await ctx.execute_task(validate_payment, input)

    # Step 2: Charge payment gateway (with idempotency key)
    charge = await ctx.execute_task(
        charge_payment_gateway, validated.amount, validated.currency, validated.idempotency_key
    )

    # Step 3: Reserve inventory — compensate on failure
    try:
        await ctx.execute_task(reserve_inventory, validated.order_id)
    except Exception as e:
        # Saga compensation: refund the charge
        await ctx.execute_task(refund_charge, charge.charge_id)
        raise e

    # Step 4: Send confirmation (best-effort, don't fail the payment)
    try:
        await ctx.execute_task(send_confirmation, validated.customer_id, validated.order_id)
    except Exception:
        pass  # non-critical

    return PaymentResult(
        charge_id=charge.charge_id,
        status="completed",
        order_id=validated.order_id,
    )

## Two layers of idempotency

The journal guarantees `charge_payment_gateway` never re-executes once its result is recorded. But there's a window the journal can't see: the worker dies *inside* the task — after the gateway captured the money, before the result was journaled. That's what the gateway idempotency key is for.

The [overview's charged-once diagram](/guides/use-cases/financial-workflows#charged-once) covers a crash *between* tasks — the journal handles that alone. This one covers a crash *inside* the charge task, where only the provider can tell the retry "you already paid."

## Design notes

- **Derive the idempotency key from the order, not the attempt.** The key must be stable for one logical payment (`input.idempotency_key`, set by the caller from the order ID). A key generated per retry would defeat the gateway's deduplication exactly when you need it.
- **Compensation can fail too.** `refund_charge` is a journaled task with retries, but if the gateway is down long enough, the workflow fails holding a captured charge. That's the correct behavior: the journal records precisely which compensations completed, giving your ops process an exact worklist instead of a mystery.
- **Best-effort is a policy, not an accident.** The confirmation's ignored error is deliberate — a receipt email must never refund a good payment. If notifications matter more than that, move them to their own workflow triggered by a completion event.
- **Use minor units in production.** The examples pass `amount` as a float for brevity; real payment systems should carry integer minor units (cents) end-to-end to avoid rounding drift.
