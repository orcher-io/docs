title: Local Development & CLI
subtitle: Run an Orcher engine on your machine and develop workflows against it
---

Everything in this section runs on your machine: an engine in Docker, a worker started from your terminal, and the `orcher` CLI to start workflows and look at them.

## What runs locally

| Piece | What it is | Where it listens |
|---|---|---|
| Engine | The container image `ghcr.io/orcher-io/orcher`. It needs a PostgreSQL 14+ database and nothing else. | gRPC on `localhost:50051`, for workers, clients and the CLI. HTTP on `localhost:8080`: the dashboard, the REST API under `/api/v1`, `/health/ready` and `/metrics`. |
| Worker | Your code: a process that connects to the engine and runs your workflows and tasks. | Nowhere. It polls the engine; the engine never calls it. |
| CLI | `orcher`, which starts the engine and starts, lists and inspects workflows. | Nowhere. |

A local engine runs without authentication, and its ports are published on `127.0.0.1` only, so nothing outside your machine can reach it.

## Prerequisites

- [Docker](https://docs.docker.com/get-docker/)
- For the language you write in: Python 3.11 or later, Node.js 22 or later, or stable Rust

## Start an engine

With the CLI ([install it first](/guides/local-development/getting-started#1-install-the-cli)):

```bash
orcher dev start --engine-version 0.7.2
```

Or without it, using the Compose file in the [quickstart repository](https://github.com/orcher-io/quickstart):

```bash
git clone https://github.com/orcher-io/quickstart.git
cd quickstart
docker compose up -d --wait
```

Both start Postgres and the engine, and return when the engine is ready. Use one or the other, not both: they publish the same ports.
