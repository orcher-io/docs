**What's happening here:**

1. **Server connection**: The SDK connects to the Orcher server via gRPC
2. **Task queue**: Workers poll the specified task queue for pending work
3. **Worker loop**: The worker polls for pending workflows and tasks and executes them

**Important**: The Orcher server manages workflow state and dispatching. Workers connect to the server and execute workflows and tasks. You can scale workers independently by running multiple instances.

## Pattern 1: Reliable Payment Processing

Let's build a payment system that survives a crash mid-payment without losing track of the money or charging twice.

### The Problem We're Solving

Payment processing is high-stakes:
- **Lose a charge**: Company loses revenue
- **Double-charge**: Customer complaints, chargebacks, reputation damage
- **Partial completion**: Charge succeeded but email failed → customer confusion
- **Fraud not checked**: Financial liability

Traditional code is brittle:

```typescript
// Traditional approach (FRAGILE!)
async function processPayment(payment) {
  const charge = await stripe.charges.create({ amount: payment.amount });
  await db.payments.insert({ chargeId: charge.id });
  await sendEmail({ template: 'receipt', to: payment.email });
  // If server crashes here, email is lost forever
  await updateUserCredits(payment.userId, payment.amount);
}
```

**Problems:**
- No automatic retry
- No idempotency
- No visibility into failures
- Manual debugging required

### The Orcher Solution: Step by Step

Let's build this properly. We'll break it into phases:

**Phase 1: The Workflow Structure**

First, understand the flow. Every step is a checkpoint, and step 2 can branch to an early rejection:

use orcher::prelude::*;

#[workflow(name = "process_payment")]
pub async fn process_payment(
    ctx: WorkflowContext,
    input: PaymentInput,
) -> Result<PaymentResult> {
    // Step 1: Validate (fast, local check)
    ctx.execute_task(validate_payment_method, input.payment_method.clone())
        .await?;

    // Step 2: Fraud check (external API)
    let fraud_score: f64 = ctx.execute_task(check_fraud, (
        input.user_id.clone(),
        input.amount,
    )).await?;

    // Decision logic in the workflow
    if fraud_score > 0.8 {
        return Err(anyhow::anyhow!("Payment flagged for fraud"));
    }

    // Step 3: Charge card (idempotent via Stripe idempotency key)
    let charge: StripeCharge = ctx.execute_task(charge_stripe, (
        input.payment_method.clone(),
        input.amount,
        input.currency.clone(),
    )).await?;

    // Step 4: Record in database
    ctx.execute_task(record_payment, PaymentRecord {
        user_id: input.user_id.clone(),
        charge_id: charge.id.clone(),
        amount: input.amount,
        status: "succeeded".to_string(),
    }).await?;

    // Step 5: Send email (idempotent - won't send twice)
    ctx.execute_task(send_receipt_email, (
        input.user_id.clone(),
        charge.receipt_url.clone(),
    )).await?;

    // Step 6: Update credits
    ctx.execute_task(update_user_credits, (
        input.user_id.clone(),
        input.amount,
    )).await?;

    Ok(PaymentResult {
        charge_id: charge.id,
        status: "succeeded".to_string(),
        receipt_url: charge.receipt_url,
    })
}

      amount: input.amount,

      throw new Error('Payment flagged for fraud');

    // Step 3: Charge card (idempotent via Stripe idempotency key)
    const charge = await ctx.executeTask(tasks.chargeStripe, {
      paymentMethod: input.paymentMethod,
      amount: input.amount,
      currency: input.currency,
    });

    // Step 4: Record in database
    await ctx.executeTask(tasks.recordPayment, {
      userId: input.userId,
      chargeId: charge.id,
      amount: input.amount,
      status: 'succeeded',
    });

    await ctx.executeTask(tasks.sendReceiptEmail, {
      userId: input.userId,

    });

    // Step 6: Update credits
    await ctx.executeTask(tasks.updateUserCredits, {
      userId: input.userId,
      amount: input.amount,
    });

    return {
      chargeId: charge.id,
      status: 'succeeded',
      receiptUrl: charge.receipt_url,
    };
  }
}

**What makes this reliable:**

1. **Each `ctx.execute_task()` is checkpointed**: If the workflow crashes, it resumes from the last checkpoint
2. **Idempotent by design**: Each task can be safely retried
3. **Decision logic isolated**: The workflow controls the flow, tasks do the work
4. **Clear error boundaries**: Any error stops the workflow; it can be retried later

#[task]
async fn validate_payment_method(method: String) -> Result<()> {
    // Validate format only (no external calls)
    if !method.starts_with("pm_") && !method.starts_with("card_") {
        return Err(anyhow::anyhow!("Invalid payment method format"));
    }
    Ok(())
}

#[task]
async fn check_fraud(user_id: String, amount: i64) -> Result<f64> {
    // Call fraud detection service
    let response = reqwest::Client::new()
        .post("https://fraud-api.example.com/check")
        .json(&serde_json::json!({
            "user_id": user_id,
            "amount": amount,
        }))
        .send()
        .await?;

    let score = response.json::<serde_json::Value>().await?["score"]
        .as_f64()
        .unwrap_or(0.0);

    Ok(score)
}

#[task]
async fn charge_stripe(
    payment_method: String,
    amount: i64,
    currency: String,
) -> Result<StripeCharge> {
    let stripe_key = std::env::var("STRIPE_SECRET_KEY")?;

    // Stripe's idempotency is built-in via their API
    let response = reqwest::Client::new()
        .post("https://api.stripe.com/v1/charges")
        .header("Authorization", format!("Bearer {}", stripe_key))
        .form(&[
            ("amount", amount.to_string()),
            ("currency", currency),
            ("payment_method", payment_method),
            ("confirm", "true".to_string()),
        ])
        .send()
        .await?;

    if !response.status().is_success() {
        return Err(anyhow::anyhow!("Stripe charge failed"));
    }

    let charge: StripeCharge = response.json().await?;
    Ok(charge)
}

#[task]
async fn record_payment(record: PaymentRecord) -> Result<()> {
    let pool = get_db_pool();

import { Tasks, Task, TaskContext } from '@orcher/sdk';
import Stripe from 'stripe';
import sgMail from '@sendgrid/mail';
import { Pool } from 'pg';

@Tasks()
class PaymentTasks {
  @Task()
  async validatePaymentMethod(ctx: TaskContext, method: string): Promise<void> {
    // Validate format only (no external calls)
    if (!method.startsWith('pm_') && !method.startsWith('card_')) {
      throw new Error('Invalid payment method format');
    }
  }

  @Task()
  async checkFraud(ctx: TaskContext, { userId, amount }: { userId: string; amount: number }): Promise<number> {
    // Call fraud detection service
    const response = await fetch('https://fraud-api.example.com/check', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ user_id: userId, amount }),
    });

    const data = await response.json();
    return data.score as number;
  }

  @Task()
  async chargeStripe(ctx: TaskContext, {
    paymentMethod,
    amount,
    currency,
  }: {
    paymentMethod: string;
    amount: number;
    currency: string;
  }): Promise<StripeCharge> {
    const stripe = new Stripe(process.env.STRIPE_SECRET_KEY!, {
      apiVersion: '2023-10-16',
    });

    // Stripe's idempotency is built-in
    const charge = await stripe.charges.create({
      amount,
      currency,
      payment_method: paymentMethod,
      confirm: true,
    });

    return {
      id: charge.id,
      receipt_url: charge.receipt_url!,
    };
  }

  @Task()
  async recordPayment(ctx: TaskContext, record: {
    userId: string;
    chargeId: string;
    amount: number;
    status: string;
  }): Promise<void> {
    const pool = getDbPool();

    // Idempotent: ON CONFLICT DO NOTHING
    await pool.query(
      `INSERT INTO payments (user_id, charge_id, amount, status, created_at)
       VALUES ($1, $2, $3, $4, NOW())
       ON CONFLICT (charge_id) DO NOTHING`,
      [record.userId, record.chargeId, record.amount, record.status]
    );
  }

  @Task()
  async sendReceiptEmail(ctx: TaskContext, { userId, receiptUrl }: { userId: string; receiptUrl: string }): Promise<void> {
    const pool = getDbPool();

    // Get user email
    const result = await pool.query('SELECT email FROM users WHERE id = $1', [userId]);
    const userEmail = result.rows[0].email;

    // Send via SendGrid (idempotent - they deduplicate)
    sgMail.setApiKey(process.env.SENDGRID_API_KEY!);

    await sgMail.send({
      to: userEmail,
      from: 'receipts@example.com',
      subject: 'Payment Receipt',
      html: 'Your payment was successful. <a href="' + receiptUrl + '">View Receipt</a>',
    });
  }

  @Task()
  async updateUserCredits(ctx: TaskContext, { userId, amount }: { userId: string; amount: number }): Promise<void> {
    const pool = getDbPool();
    const credits = Math.floor(amount / 100); // Convert cents to credits

    // Idempotent: adds credits (not set)
    await pool.query('UPDATE users SET credits = credits + $1 WHERE id = $2', [
      credits,
      userId,
    ]);
  }
}

// Helper types and functions
interface StripeCharge {
  id: string;
  receipt_url: string;
}

function getDbPool(): Pool {
  return new Pool({
    connectionString: process.env.DATABASE_URL,
  });
}

## Pattern 2: Webhook Processing

Webhooks are notoriously tricky. Let's build a reliable webhook handler.

### The Webhook Problem

External services (Stripe, Twilio, GitHub, etc.) send HTTP requests to your server when events occur. Problems:

1. **Duplicate webhooks**: Services retry on timeout, you process twice
2. **Out-of-order delivery**: Event A arrives after Event B
3. **Lost webhooks**: Your server is down, webhook is lost forever
4. **Slow processing**: Webhook times out, service retries, you process twice
5. **No visibility**: Did we process this webhook? What happened?

**Traditional approach:**

```typescript
// Traditional (FRAGILE!)
app.post('/webhooks/stripe', async (req, res) => {
  const event = req.body;

  // Quick check for duplicate
  const exists = await redis.get('webhook:' + event.id);
  if (exists) {
    return res.json({ received: true });
  }

  // Process synchronously (blocks response)
  try {
    await processEvent(event);
    await redis.set('webhook:' + event.id, 'processed', 'EX', 86400);
    res.json({ received: true });
  } catch (error) {
    // Error - but webhook service already timed out
    // Will retry and we'll process twice!
    res.status(500).json({ error: error.message });
  }
});
```

**Problems:**
- Synchronous processing (slow response)
- Redis dependency for deduplication
- If Redis is down, duplicate processing
- If processing is slow, webhook times out
- No automatic retries on failure

## Pattern 3: Distributed Transactions (Saga Pattern)

Let's build a complex order fulfillment system that spans multiple services.

### The Distributed Transaction Problem

Your order flow:
1. Create order in your database
2. Reserve inventory (external inventory service)
3. Charge customer (Stripe)
4. Trigger fulfillment (external warehouse service)

**What if step 3 fails?**
- Order created ✓
- Inventory reserved ✓
- Payment failed ✗
- Fulfillment not triggered ✗

Now you need to:
- Release the inventory reservation
- Cancel the order
- Notify the customer

This is the **saga pattern**: each step has a compensating action.

### The Orcher Saga Implementation

#[workflow(name = "order_fulfillment")]
pub async fn order_fulfillment(
    ctx: WorkflowContext,
    order: OrderInput,
) -> Result<OrderResult> {
    let total_amount = order.items.iter()
        .map(|i| i.price * i.quantity as i64)
        .sum();

    // Step 1: Create order (compensatable)
    let order_id: String = ctx.execute_task(create_order, (
        order.user_id.clone(),
        order.items.clone(),
        total_amount,
    )).await?;

    // Step 2: Reserve inventory (compensatable)
    let reservation = match ctx.execute_task(
        reserve_inventory,
        order.items.clone(),
    ).await {
        Ok(res) => res,
        Err(e) => {
            // Compensate: cancel order
            ctx.execute_task(cancel_order, order_id.clone()).await?;
            return Err(e);
        }
    };

    // Step 3: Process payment (compensatable)
    let payment_id = match ctx.execute_task(
        charge_payment,
        (order.payment_method.clone(), total_amount),
    ).await {
        Ok(id) => id,
        Err(e) => {
            // Compensate: release inventory and cancel order
            ctx.execute_task(release_inventory, reservation.id).await?;
            ctx.execute_task(cancel_order, order_id.clone()).await?;
            return Err(e);
        }
    };

    // Step 4: Confirm order (point of no return)
    ctx.execute_task(confirm_order, order_id.clone()).await?;

    // Step 5: Trigger fulfillment
    ctx.execute_task(trigger_fulfillment, (
        order_id.clone(),
        reservation.id,
    )).await?;

    Ok(OrderResult {
        order_id,
        status: "confirmed".to_string(),
        total_amount,
    })
}

      userId: order.userId,
      items: order.items,
      totalAmount,
    });

    // Step 2: Reserve inventory (compensatable)
    let reservation: InventoryReservation;
    try {
      reservation = await ctx.executeTask(orderTasks.reserveInventory, order.items);
    } catch (error) {
      // Compensate: cancel order
      await ctx.executeTask(orderTasks.cancelOrder, orderId);
      throw error;
    }

    // Step 3: Process payment (compensatable)
    let paymentId: string;
    try {
      paymentId = await ctx.executeTask(orderTasks.chargePayment, {
        paymentMethod: order.paymentMethod,
        amount: totalAmount,
      });
    } catch (error) {
      // Compensate: release inventory and cancel order
      await ctx.executeTask(orderTasks.releaseInventory, reservation.id);
      await ctx.executeTask(orderTasks.cancelOrder, orderId);
      throw error;
    }

    // Step 4: Confirm order (point of no return)
    await ctx.executeTask(orderTasks.confirmOrder, orderId);

    // Step 5: Trigger fulfillment
    await ctx.executeTask(orderTasks.triggerFulfillment, {
      orderId,
      reservationId: reservation.id,
    });

    return {
      orderId,
      status: 'confirmed',
      totalAmount,
    };
  }
}

**Key Points:**

1. **Try-Catch Compensation**: Each step that can fail has explicit compensation logic
2. **Ordering Matters**: Steps are ordered to minimize compensation complexity
3. **Point of No Return**: After `confirm_order`, we don't compensate (customer has been charged)
4. **Automatic Retry**: If `trigger_fulfillment` fails, Orcher retries automatically

### Understanding Compensation

**Scenario 1: Payment fails — roll back in reverse.** The charge is declined *before* the point of no return, so every completed step is undone by its compensation, newest first.
